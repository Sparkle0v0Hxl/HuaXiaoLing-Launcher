# 日志：安装目录里的卸载入口（硬链接方案）

## 用户原话

- m09306：「哪里有应用？设置页还有单独开一个这按钮？而且打不开启动器卸载咋办？」
- m09309：「设置页不用装卸载按钮」
- **m09336：「我的意思是文件夹里应该有个卸载的的Uninstall」**
- m09347：「我也才懂你意思，你的意思，就是windows的设置应用里，去点卸载」

## 需求拆解

用户要**两个入口都能卸载**：

1. Windows「设置 → 应用 → 花筱灵启动器 → 卸载」—— 走注册表 `UninstallString`，已实现（指向 `花筱灵启动器.exe --uninstall`）。
2. **安装目录里有个能双击的 `Uninstall xxx.exe`** —— 传统软件习惯，用户会去文件夹里找。本次新增。

明确**不要**的：设置页里加卸载按钮（m09309 否决）。

## 方案选择：为什么用硬链接

历史教训（2026-11-25 改造）：旧安装器把**安装器自己**复制一份成 `安装目录\Uninstall.exe`。但 Electron 的规则是「执行文件同目录下的 `resources\app.asar` 就是我的程序」，而安装目录里的 `app.asar` 是**启动器本体** —— 所以双击那个 Uninstall.exe 跑起来的是启动器主界面。用户报的「卸载里面掺进安装」就是这个。

三个候选：

| 方案 | 体积 | 能否正常工作 | 结论 |
|---|---|---|---|
| 复制一份 exe | +250 MB | 双击跑成主界面（同上） | ✗ |
| 独立的小 launcher exe | +几百 KB | 需要额外编译一个 exe，还要带图标/版本信息 | 可行但复杂 |
| **硬链接** | **+0** | 同 inode，Electron 按 execPath 找 resources，路径就是安装目录 | ✓ |

硬链接的限制：**没法带命令行参数**（双击就是裸启动，`process.argv` 里没有 `--uninstall`）。

解法：主程序改成**按 exe 文件名**也认卸载模式。

## 实现

### 1. 主程序认文件名（`electron/main.js`）

```js
const isUninstallMode =
  process.argv.includes('--uninstall') || /^uninstall/i.test(path.basename(process.execPath));
```

原来的单实例锁跳过逻辑不变（`gotLock = isUninstallMode ? true : ...`）。

### 2. 安装器建硬链接（`installer/main.js`）

新增常量：

```js
const UNINSTALL_EXE = `Uninstall ${APP_NAME}.exe`;
```

安装流程在生成 `花筱灵启动器.exe` 之后（②b 步）：

```js
const uninstExe = path.join(installDir, UNINSTALL_EXE);
try { if (fs.existsSync(uninstExe)) fs.rmSync(uninstExe, { force: true }); } catch {}
try {
  fs.linkSync(path.join(installDir, APP_EXE), uninstExe);
} catch (linkError) {
  // 非 NTFS（FAT32/exFAT）不支持硬链接，退回复制
  await fsp.copyFile(path.join(installDir, APP_EXE), uninstExe);
}
```

失败只 toast 警告，不阻断安装（用户能装上比省 250MB 重要）。

**关键顺序问题**：后面「清理历史残留卸载器」的循环会枚举所有 `/^uninstall[^\\/]*\.exe$/i` 并删掉 —— 必须**跳过刚建的这个**：

```js
if (name.toLowerCase() === UNINSTALL_EXE.toLowerCase()) continue;
```

### 3. 老用户补建（`electron/migrations.js`）

走**完整包**更新的老用户不会重跑安装器，所以加一条迁移：

```js
{
  id: 'uninstall-shortcut-v2',
  since: '2.14.0',
  desc: '安装目录里少一个能双击的卸载入口...',
  paths: [],
  uninstallShortcut: true,   // 特殊处理标记
}
```

执行逻辑：`installDir = path.dirname(process.execPath)` → 已存在就跳过 → `fs.linkSync` 失败退 `fs.copyFileSync` → 写标记。

同时给 `APP_DISPLAY_NAME = '花筱灵启动器'` 常量（迁移模块刻意不依赖 Electron，拿不到 `app.getName()`）。

### 4. 卸载流程

`electron/uninstall.js` 的 `removeProgramFiles()` 枚举一级条目删，`KEEP_TOP_LEVEL` 只保留 `data` —— 硬链接会被正常删除。正在运行的 exe 本身（就是那个硬链接）会 `EPERM` 进 `pending`，交给 `schedulePurge()` 的分离 PowerShell 重试 12 次。

## 踩坑

1. **`node --check` 抓不到未定义变量**。我写了 `APP_DISPLAY_NAME` 但没定义，`node --check` 照样通过，运行时才会 `ReferenceError`。以后改模块必须实际 require + 调用一次。
2. **dry-run 的日志文案骗人**。`repairUninstallRegistry` 在 dry-run 下不写注册表，但 `migrations.js` 的日志无条件打印「卸载入口已指向 X」，看起来像真改了。已改成 `dryRun ? '将指向（预演）' : '已指向'`。
3. **安装器清理循环会删掉刚建的硬链接**。②b 建、② 清理，顺序错了就白建。必须显式跳过。
4. **PowerShell 双引号里反斜杠不是转义字符**（前一轮踩的）：写 `\\` 会得到双反斜杠，写单 `\`。
